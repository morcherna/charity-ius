# Phase 0: Research

## Решение: загрузка выписки 1C «клиент-банк»

**Decision**: Система принимает текстовый файл 1C-клиент-банк,
проверяет обязательные секции и реквизиты и сохраняет операции после анализа.

**Rationale**: Это соответствует интеграции без прямого банковского API
и позволяет обнаруживать повторные загрузки до изменения остатков.

**Alternatives considered**: Прямой банковский API отклонён решением проекта: достаточно файлового обмена;
ручной ввод сохраняется как запасной способ ввода отдельных операций.

## Решение: детерминированное сопоставление выписки

**Decision**: Сопоставление выполняется по ИНН контрагента, сумме и номеру документа.
Однозначное совпадение предлагается пользователю, неоднозначное требует выбора бухгалтера.

**Rationale**: Правила воспроизводимы при отключённом ИИ и не проводят платежи автоматически.
ИИ может ранжировать варианты, но решение принимает пользователь.

**Alternatives considered**: Сопоставление только по сумме отклонено как ненадёжное;
автоматическое проведение отклонено конституцией.

## Решение: резервное копирование

**Decision**: Для RPO не более 1 часа резервные копии создаются не реже одного раза в час.
Ежедневная проверка восстановления подтверждает возможность восстановления в пределах RTO 4 часа.

**Rationale**: Суточное копирование без промежуточных точек не гарантирует RPO.

**Alternatives considered**: Только суточное резервное копирование отклонено
как несовместимое с установленной точкой восстановления.

## Решение: обмен табличными и печатными данными

**Decision**: XLSX и CSV используются для табличного обмена,
PDF формируется серверной обработкой.

**Rationale**: Требуемые форматы заданы независимо от конкретной реализации.

**Alternatives considered**: Ручное форматирование не обеспечивает единообразие;
внешняя онлайн-конвертация не используется из-за минимизации передачи данных.

## Решение: ролевой доступ

**Decision**: Для каждой операции задаётся матрица ролей.
Бухгалтер анализирует выписки, уполномоченный пользователь утверждает и проводит платеж,
администратор управляет доступом, но не финансовым утверждением.

**Rationale**: Разделение ролей минимизирует права и обеспечивает контроль.

**Alternatives considered**: Общая роль сотрудника отклонена из-за риска превышения полномочий.
